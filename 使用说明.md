## 1. 安装与首次启动 / Installation and first launch

### Windows

**中文**
1. 将 ZIP 完整解压到可写文件夹（例如 `D:\Research\SRPRecorder2027\`）。程序是绿色的，无安装器、无需管理员权限。
2. 运行 `SRCRec\SRPRecorder2027.exe`。不要单独移动 exe，旁边的 `SRPRecorder2027.exe.config` 决定高 DPI 与长路径行为。
3. 首次启动自动创建 `PersonalWorkspaceSRRec\`（含 `Mat_Local`、`Reference`、`Public_Temp`）与 `References\Default\`。
4. 若出现 SmartScreen 提示，点「更多信息 → 仍要运行」。程序未购买代码签名证书。
5. 同一时间只能运行一个实例；重复启动会提示切换到已有窗口。

**English**
1. Extract the ZIP completely into a writable folder (e.g. `D:\Research\SRPRecorder2027\`). The app is portable: no installer, no admin rights.
2. Run `SRCRec\SRPRecorder2027.exe`. Do not move the exe alone — the adjacent `SRPRecorder2027.exe.config` controls high-DPI and long-path behaviour.
3. First launch creates `PersonalWorkspaceSRRec\` (with `Mat_Local`, `Reference`, `Public_Temp`) and `References\Default\`.
4. If SmartScreen appears, choose “More info → Run anyway”. The app has no commercial code-signing certificate.
5. Only one instance runs at a time; launching again asks you to switch to the existing window.

### macOS

**中文**
1. 打开 DMG，把 `ResearchProgressRecorder.app` 拖入 `Applications`（覆盖旧版前先退出程序）。
2. 首次打开被 Gatekeeper 拦截时：右键「打开」，或执行
   `xattr -dr com.apple.quarantine /Applications/ResearchProgressRecorder.app`。
3. 用户数据在 `~/Library/Application Support/ResearchProgressRecorder/`，不在 app 包内；替换 app 不丢数据。
4. DMG 内 `uninstall-macos.command` 默认把 app 移到废纸篓并保留研究数据。

**English**
1. Open the DMG and drag `ResearchProgressRecorder.app` into `Applications` (quit the old version first).
2. If Gatekeeper blocks the first launch: right-click → Open, or run
   `xattr -dr com.apple.quarantine /Applications/ResearchProgressRecorder.app`.
3. User data lives in `~/Library/Application Support/ResearchProgressRecorder/`, outside the app bundle; replacing the app keeps it.
4. `uninstall-macos.command` in the DMG moves the app to the Trash and keeps research data by default.

## 2. 登录与令牌 / Signing in and tokens

**中文**
- 前提：GitHub 账号已被邀请加入私有仓库 `bacoyc0928-art/research-data` 并已接受邀请。
- 位置：Windows 窗口左下角登录面板，macOS 窗口底部登录栏；粘贴**自己的**令牌，点「登录 / Sign In」。
- 令牌类型：仓库所有者可用 fine-grained PAT（只勾 `research-data` 的 Contents 读写）；**外部协作者必须用 classic PAT 并勾选 `repo`**，fine-grained 访问他人账号的私有仓库一律 404。
- 登录分两步：先验证身份，再验证仓库可读；分别提示结果。
- 令牌**只存在内存**：不写磁盘、不写钥匙串/凭据管理器、不打印、不进日志；每次启动重新登录。
- 「显示 / Show」可临时显示明文；登录后按钮自动隐藏。
- 「退出 / Sign Out」二次确认后**直接关闭程序**。
- 未登录：不能进入「参考文献与资料」，不能上传/下载/发帖/改说明/新建文档/改类别，也不会写任何 JSON。

**English**
- Prerequisite: your GitHub account is invited to the private repository `bacoyc0928-art/research-data` and has accepted.
- Where: bottom-left panel on Windows, bottom bar on macOS. Paste **your own** token and press “Sign In”.
- Token type: the repository owner may use a fine-grained PAT limited to `research-data` (Contents read/write). **External collaborators must use a classic PAT with `repo`** — fine-grained tokens always return 404 on another account’s private repository.
- Sign-in is two-stage: identity first, repository access second, each with its own message.
- The token **stays in memory only**: never written to disk, Keychain or Credential Manager, never printed or logged. Every launch needs a fresh sign-in.
- “Show” reveals the token temporarily and hides itself after sign-in.
- “Sign Out” asks for confirmation and then **closes the program**.
- While signed out you cannot open References, upload, download, post, edit Help, create documents or edit categories; no JSON is written.

| 提示 / Message | 含义 / Meaning | 处理 / Fix |
|---|---|---|
| `401` | 令牌无效、过期或撤销 / invalid, expired or revoked | 重新生成令牌 / create a new token |
| `403` | 无写权限 / no write access | classic PAT 勾 `repo`；fine-grained 勾 Contents 读写 |
| `404` | 未接受邀请、令牌类型不对或仓库名不符 / invite missing, wrong token type or repo name | 先在浏览器确认能打开仓库；外部协作者换 classic PAT |

## 3. 六个栏目 / The six pages

界面固定中英双语并显，没有语言开关。左侧（Windows）或标签栏（macOS）依次是：**团队研究、Quick Post、参考文献与资料、本地进度、团队同步、使用说明**。每个栏目有独立的未读红点，点进即清除；红点只在登录后计算，首次启动以当时状态为基线。

The interface is always bilingual; there is no language switch. The six sections are Team Research, Quick Post, References & Materials, Local Progress, Team Sync and Help. Each section has its own unread dot, cleared when you enter it; dots are computed only when signed in and are baselined on first launch.

### 3.1 团队研究 / Team Research

**中文**
- 登录后点「刷新」读取仓库协作者与 `team/`：除你之外的成员统一显示「项目成员」，你的卡片/行显示本人账号。
- 你的卡片：**打开 Reference**（`PersonalWorkspaceSRRec\Reference`）与 **撤除参考资料**。
- 他人卡片：**打开文件夹**（macOS 选中成员后「打开成员文件」）→ 下载其 `references/` 与 `progress/` 到 `Public_Temp\<成员>\` 并列出文件。
- **下载并合并团队参考资料**：把每位成员的 `references/` 下载到 `Public_Temp\<成员>\references\`，并加入参考资料列表；不会复制进你的 `Reference`。
- 刷新只读；首次上传时才创建远端 `team\<账号>\profile.json`。
- 下载失败不会清空旧副本，旧副本以 `.bak-…` / `.dl-…` 同级目录保留。

**English**
- After signing in, “Refresh” reads collaborators and `team/`: everyone except you is labelled “Project member”; your card/row shows your login.
- Your card: **Open Reference** (`PersonalWorkspaceSRRec\Reference`) and **Remove References**.
- Another member’s card: **Open Folder** (macOS: select the member, then “Open Member Files”) → downloads their `references/` and `progress/` into `Public_Temp\<member>\` and lists the files.
- **Download Team References** pulls every member’s `references/` into `Public_Temp\<member>\references\` and adds them to the references list; it does not copy them into your own `Reference`.
- Refresh is read-only; `team/<login>/profile.json` is created on the first upload.
- A failed download never wipes an existing copy; old copies stay as sibling `.bak-…` / `.dl-…` directories.

### 3.2 Quick Post

**中文**
- 多行输入框写内容 →「发布」；帖子存为 `posts\<UTC时间>-<账号>-<4位随机>.txt`，全员可见。
- 便签卡片显示作者 · 时间 + 两行预览；点卡片或标题看全文。
- 「已阅」后从未读列表消失，进入「历史记录」（双击重开）；只能删自己的帖子。
- 有新帖时栏目亮红点；页面约每 90 秒自动刷新，也可重新进入。
- 发帖/删帖写活动日志，不写单独改动日志。

**English**
- Write in the multi-line box → “Publish”. Posts are stored as `posts/<UTC time>-<login>-<4 random hex>.txt` and are visible to everyone.
- Sticky-note cards show author · time plus a two-line preview; click to read the full text.
- “Mark Read” moves a post from the unread list into History (double-click to reopen); you can delete only your own posts.
- New posts light the section’s red dot; the page refreshes about every 90 seconds, or when re-entered.
- Publishing/deleting writes the activity log, not a separate change log.

### 3.3 参考文献与资料 / References & Materials

**中文**
- 三块：**团队默认资料库**（`References\Default\`，只读镜像）、**我的参考资料**（`PersonalWorkspaceSRRec\Reference\`）、**他人内容（临时）**（`Public_Temp\<成员>\`，退出即清空）。
- 双击卡片/文件打开；文件夹卡片打开资源管理器/Finder。
- 本页只读：新增、上传、撤除都在团队同步页完成。
- 未登录不能进入本页（会跳回团队研究并提示）。

**English**
- Three blocks: **Default Library** (`References\Default\`, read-only mirror), **My References** (`PersonalWorkspaceSRRec\Reference\`), and **Others (temp)** (`Public_Temp\<member>\`, cleared on exit).
- Double-click a card/file to open it; a folder card opens Explorer/Finder.
- This page is read-only: add, upload and remove happen on Team Sync.
- Signed-out users cannot open it (the app returns to Team Research with a hint).

### 3.4 本地进度 / Local Progress

**中文**
- 顶部显示当前进度文件夹（默认 `PersonalWorkspaceSRRec`）；「选择文件夹」可换到自己的专用研究目录（不能选程序目录或其上级）。
- 表格列出文件（名称 / 大小 / 修改时间），双击打开，「刷新」重读。
- 「新建文档」输入项目名 → 生成 `Document_<日期> <项目>.docx` 并打开；模板为 标题 → 项目 → 日期 → 目的 → 留白，中文楷体、西文 Times New Roman。
- 本地保存不等于上传，需到团队同步点「上传本地进度」。

**English**
- The top shows the current progress folder (default `PersonalWorkspaceSRRec`); “Choose Folder” switches to a dedicated research folder (the program folder or its parents are rejected).
- The table lists name, size and modified time; double-click to open, “Refresh” to re-read.
- “New Document” asks for a project name and creates `Document_<date> <project>.docx`; the template is title → project → date → purpose → blank page, KaiTi for Chinese and Times New Roman for Latin text.
- Saving locally does not upload; use Upload Local Progress on Team Sync.

### 3.5 团队同步 / Team Sync

**中文**：页面只显示「已绑定仓库：bacoyc0928-art/research-data · main」，无需填写任何配置。每个动作先弹出清单，只处理勾选项。

**English**: the page only shows “Bound repository: bacoyc0928-art/research-data · main”; nothing to configure. Every action opens a checklist and processes only the checked items.

### 3.6 使用说明 / Help

**中文**
- 正文可编辑，所有成员共享 `help/help.md`。
- 「上传到 GitHub」写入 `help/help.md`，并追加 `help/changelog.json` 与活动日志；「读取云端版本」重新拉取；「恢复默认」回到内置文本；「改动日志」查看历史。
- Windows 另存草稿 `help_local.md`；macOS 草稿只在当前窗口内。
- 未登录时正文只读，上传/读取不可用。

**English**
- The body is editable and shared as `help/help.md`.
- “Upload to GitHub” writes `help/help.md`, appends `help/changelog.json` and the activity log; “Load From GitHub” re-fetches; “Restore Default” returns to the built-in text; “Change Log” lists past edits.
- Windows keeps a draft in `help_local.md`; macOS keeps it only in the current window.
- While signed out the body is read-only and upload/reload are unavailable.

## 4. 同步动作与数据流向 / Sync actions and data flow

| 动作 / Action | 作用 / What it does | 落点 / Destination |
|---|---|---|
| 下载他人内容 / Download Team Files | 列出其他成员（含 references 数量、是否有 progress），勾选后逐个下载 | `PersonalWorkspaceSRRec\Public_Temp\<成员>\` |
| 下载默认资料库 / Download Default Library | 列出 `default/` 文件并标注新增/已存在，勾选后逐文件下载 | `References\Default\`，覆盖前留 `.bak-<时间戳>` |
| 上传参考资料 / Upload References | 默认列 `Reference` 中的文件，可「添加文件」补选；同名文件拒绝 | `team\<账号>\references\<文件名>` + 合并 `references.json` |
| 上传本地进度 / Upload Local Progress | 默认列 `Mat_Local`（为空时列进度文件夹），勾选后上传 | `team\<账号>\progress\<相对路径>` |
| 撤除我上传的参考资料 / Remove My Uploaded References | 只列**你自己**上传的文件，勾选 + 二次确认 | 删除远端文件与清单条目 |
| 查看活动日志 / Activity Log | 读取公开日志 + 本人明细 | 只读 |

**中文**
- 上传是逐文件的，可能部分成功；重试会覆盖同名文件，不会自动删除远端旧文件。
- 撤除只影响团队区与清单；本机 `Reference` 中的同名副本当前不会自动删除，需要时请手动清理。
- 上传本地进度若用「添加文件」选择进度文件夹以外的文件，请先复制进 `Mat_Local`，否则远端相对路径可能不正确。
- 活动日志动作：登录、上传参考资料、上传本地进度、撤除参考资料、下载他人内容、下载默认资料库、发布/删除帖子、更新使用说明；公开日志 ≤2000 条、本人明细 ≤500 条，时间均为 UTC。

**English**
- Uploads are per file and may partially succeed; retrying overwrites same-named files and never deletes remote older files.
- Removal only affects the team area and the manifest; a same-named copy in your local `Reference` is not deleted automatically — remove it manually if needed.
- For Upload Local Progress, if you use “Add files” outside the progress folder, copy those files into `Mat_Local` first, otherwise the remote relative path may be wrong.
- Logged actions: sign-in, reference upload, progress upload, reference removal, team download, default-library download, post publish/delete, help update. The public log holds up to 2,000 entries, your private detail up to 500; all times are UTC.

## 5. 数据存储 / Data storage

程序没有自建服务器：团队数据全部在私有仓库 `bacoyc0928-art/research-data`，本机只保留工作副本、缓存与配置；程序源码、安装包与文档在公开仓库 `research-progress-recorder`。

There is no self-hosted server: team data lives in the private repository `bacoyc0928-art/research-data`; each machine keeps only working copies, caches and settings. Source, installers and docs live in the public repository `research-progress-recorder`.

### 5.1 Windows 本机 / Windows local

```
SRCRec\                            程序与数据根目录（exe 所在处，可整体搬移）
├─ SRPRecorder2027.exe             程序 0.2.3
├─ SRPRecorder2027.exe.config      高 DPI / 长路径配置，必须随 exe 保留
├─ research_log.json               旧版研究记录
├─ workspace.json                  工作区路径
├─ progress.json                   进度文件夹路径（改过文件夹才有）
├─ sync_config.json                绑定仓库信息（owner/repo/branch，无令牌）
├─ news.json                       各栏目未读红点状态
├─ data_version.txt                一次性迁移标记，固定 0.2.0
├─ upgrade_cleanup.log             迁移删除记录
├─ help_local.md                   使用说明本机草稿
├─ References\
│  └─ Default\                    团队默认资料库镜像（只读）
└─ PersonalWorkspaceSRRec\        默认本地进度文件夹
   ├─ Mat_Local\                  个人非参考资料（上传本地进度的默认来源）
   ├─ Reference\                  个人参考资料（上传参考资料的默认来源）
   ├─ Public_Temp\                他人内容临时区（启动清空、退出清空）
   └─ references.json             上传后缓存的资料清单
```

| 路径 / Path | 内容 / Contents | 规则 / Rule |
|---|---|---|
| `SRCRec\*.json` | 配置与状态 / config and state | 程序自写，勿手改 / app-written, do not edit |
| `References\Default\` | 团队默认库 / default library | 只由下载默认库更新 / updated only by Download Default Library |
| `PersonalWorkspaceSRRec\Mat_Local\` | 个人非参考资料 / personal non-reference files | 上传本地进度的默认来源 / default progress-upload source |
| `PersonalWorkspaceSRRec\Reference\` | 个人参考资料 / personal references | 参考资料页显示；上传参考资料的默认来源 / shown on References; default upload source |
| `PersonalWorkspaceSRRec\Public_Temp\` | 他人内容 / others’ files | 启动与退出清空 / cleared on start and exit |

### 5.2 macOS 本机 / macOS local

```
/Applications/ResearchProgressRecorder.app        只放程序 / program only
~/Library/Application Support/ResearchProgressRecorder/
├─ config.json                     进度文件夹、登录名、未读状态
├─ research_log.json               旧版研究记录
├─ data_version.txt                迁移标记 0.2.0
├─ upgrade_cleanup.log
└─ SRCRec\
   ├─ References\Default\          团队默认资料库
   └─ PersonalWorkspaceSRRec\
      ├─ Mat_Local\                个人非参考资料
      ├─ Reference\                个人参考资料（上传副本暂存 Reference\references\）
      └─ Public_Temp\              他人内容（启动/退出清空）
```

**中文**：app 包只放程序；替换 app 不影响 Application Support 中的数据。macOS 0.2.3 上传参考资料时，本机副本放在 `Reference\references\` 子目录（Windows 直接放在 `Reference\`），下一版统一。

**English**: the app bundle holds only the program; replacing it does not affect Application Support. In macOS 0.2.3 the local copy of uploaded references goes into `Reference\references\` (Windows uses `Reference\` directly); this will be unified in the next release.

### 5.3 私有仓库 / Private team repository

```
research-data/
├─ team\<账号>\
│  ├─ references\<文件>            上传的参考资料本体
│  ├─ references.json              该账号的资料清单
│  ├─ progress\<相对路径>          本地进度文件夹的镜像
│  └─ profile.json                 首次上传时自动创建
├─ default\<文件>                  团队默认资料库（成员只读）
├─ logs\public\activity.json       公开活动日志（≤2000 条）
├─ logs\private\<账号>\activity.json 本人明细（≤500 条）
├─ help\help.md                    全员共享的使用说明
├─ help\changelog.json             说明改动日志（≤200 条）
├─ posts\<UTC时间>-<账号>-<4位随机>.txt  Quick Post 帖子
├─ posts\read\<账号>.json          已阅帖子 id
└─ sync\                           0.0.2 遗留，只读保留
```

**中文**：`team/<账号>` 只是程序约定的路径分隔，不是 GitHub 权限边界——能写该仓库的人技术上可以改别人的目录，请只邀请信任的协作者。公开程序仓库只有所有者可写，普通成员即使登录也无法写它。

**English**: `team/<login>` is an application convention, not a GitHub permission boundary — anyone who can write the repository can technically edit another member’s folder, so invite only trusted collaborators. The public program repository is writable only by its owner.

### 5.4 会上传与不会上传 / What is and is not uploaded

**中文**：会上传——勾选的文件本体、参考资料清单、首次上传创建的 `profile.json`、活动日志、帖子、使用说明。不会上传——令牌、本机配置 JSON（`workspace.json`、`sync_config.json`、`news.json`、`progress.json`）、未勾选文件、`Public_Temp` 中他人文件、`Mat_Local` 中未选中的文件。

**English**: Uploaded — the exact checked files, the references manifest, `profile.json` on first upload, activity logs, posts, the help page. Not uploaded — the token, local config JSON (`workspace.json`, `sync_config.json`, `news.json`, `progress.json`), unchecked files, other members’ files in `Public_Temp`, unselected files in `Mat_Local`.

## 6. 同步机制与限制 / Sync mechanics and limits

**中文**
- **全手动**：没有后台监听或实时同步；改完文件要自己上传，别人要自己下载。
- **不做合并**：两人改同一路径时，后上传覆盖先上传，没有 diff 或冲突解决；请按成员目录分工并备份。
- **无远端删除联动**：上传只新增/覆盖，不删远端旧文件；只有「撤除我上传的参考资料」会删远端。
- **原子写入**：本地先写临时文件再替换；清单/日志写入遇 409/422 重试 3 次。
- **网络**：依赖 `api.github.com`；大文件、慢网或代理可能超时；失败不会破坏旧数据，可重试。
- **配额**：应用层 50 MiB/文件；GitHub 单文件 100 MB、仓库建议 1 GB 内。

**English**
- **Fully manual**: no watcher, no real-time sync; you upload after editing, others download to receive.
- **No merging**: if two people change the same path, the later upload wins; there is no diff or conflict resolution — divide work by member folder and keep backups.
- **No remote deletion on upload**: uploads only add/overwrite; only “Remove My Uploaded References” deletes remote files.
- **Atomic writes**: local writes go to a temp file first; manifest/log writes retry three times on 409/422.
- **Network**: relies on `api.github.com`; large files, slow links or proxies may time out; failures never destroy old data and can be retried.
- **Limits**: 50 MiB per file at the app layer; GitHub caps a file at 100 MB and recommends repositories under 1 GB.

## 7. 安全与隐私 / Security and privacy

**中文**
- 令牌只在内存，通过 `Authorization: Bearer` 发往 `api.github.com`；不落盘、不打印、不进日志、不进 git。
- 团队数据在私有仓库；下载文件名/路径会校验，拒绝越界、非法文件名与符号链接。
- 上传前检查 50 MiB/文件，拒绝目录联接与 Windows 非法名。
- CI 构建任务只有 `contents: read`；发布任务使用仅对公开程序仓库有效的短期令牌，不接触数据仓库。
- 没有代码签名/公证：只影响首次安装提示，不影响数据；写入始终是「临时文件 + 原子替换 + 备份」。

**English**
- The token stays in memory and is sent as `Authorization: Bearer` to `api.github.com`; it is never written, printed, logged or committed.
- Team data lives in a private repository; downloaded names/paths are validated, rejecting escapes, invalid names and symlinks.
- Uploads are capped at 50 MiB per file; junctions and Windows-invalid names are refused.
- CI build jobs are `contents: read`; the publish job uses a short-lived token valid only for the public program repository and never touches the data repository.
- No code signing/notarization: this affects only first-launch warnings, not data; every write is “temp file → atomic replace → backup”.

## 8. 升级、备份与卸载 / Upgrade, backup and uninstall

**中文**
- **升级**：先退出程序 → Windows 整目录替换 `SRCRec\`（保留 `.exe.config`）；macOS 用新 app 覆盖 `Applications` 中的旧版。配置、日志、下载缓存与个人资料都会保留。
- **迁移标记**：`data_version.txt` 固定为 `0.2.0`，只有从更早版本首次升级时清理一次；0.2.3 不会重复清理。
- **备份**：Windows 复制整个 `SRCRec\`；macOS 复制 `~/Library/Application Support/ResearchProgressRecorder/`；远端数据另有 GitHub 历史。
- **换电脑**：复制上述目录 → 登录 → 按需重新下载默认库与他人内容；令牌不会迁移。
- **卸载**：Windows 运行 `卸载SRPRecorder2027.exe`（默认保留研究文件）；macOS 运行 DMG 内的 `uninstall-macos.command`（默认移到废纸篓、保留数据）。卸载不会撤销令牌，请到 GitHub 自行撤销。

**English**
- **Upgrade**: quit the app → on Windows replace the whole `SRCRec\` folder (keep `.exe.config`); on macOS overwrite the old app in `Applications`. Config, logs, download cache and personal files are preserved.
- **Migration marker**: `data_version.txt` stays `0.2.0`; the cleanup runs only when upgrading from an older release and never repeats on 0.2.3.
- **Backup**: copy the whole `SRCRec\` folder (Windows) or `~/Library/Application Support/ResearchProgressRecorder/` (macOS); remote data also has GitHub history.
- **New machine**: copy that folder → sign in → re-download the default library and team files as needed. The token is never migrated.
- **Uninstall**: run `卸载SRPRecorder2027.exe` on Windows (research files kept by default); run `uninstall-macos.command` from the DMG on macOS (app to Trash, data kept). Uninstalling does not revoke the token — revoke it on GitHub yourself.

## 9. 常见问题 / FAQ

**中文**
1. **登录成功但看不到成员或帖子？** 确认已接受私有仓库邀请，再点「刷新」。fine-grained 令牌访问他人私有仓库会 404，换 classic PAT。
2. **下载 404 或附件打不开？** 从 Releases 页面下载，不要用仓库根目录的历史文件；核对完整 URL 与 `SHA256SUMS.txt`。
3. **红点不出现或不消失？** 红点只在登录后计算，进入栏目即清除，首次启动不会全亮。
4. **上传显示部分成功？** 多文件上传不是事务；重新上传会覆盖同名文件，不会删远端旧文件。
5. **提示文件超过 50 MiB？** 拆分或压缩后再传；GitHub 侧还有 100 MB 硬上限。
6. **Word 打不开或新建失败？** 关闭正在占用该文件的 Word；确认进度文件夹可写。
7. **macOS 提示无法验证开发者？** 右键「打开」，或执行第 1 节的 `xattr` 命令。
8. **两个人改同一个文件？** 后上传覆盖先上传；请按成员目录分工，重要文件先备份。

**English**
1. **Signed in but no members or posts?** Accept the private-repo invitation, then press Refresh. A fine-grained token returns 404 on another account’s private repository — use a classic PAT.
2. **404 or a broken download?** Download from the Releases page, not legacy files in the repo root; check the full URL and `SHA256SUMS.txt`.
3. **Dot missing or stuck?** Dots are computed only when signed in, clear when you enter the section, and are baselined on first launch.
4. **Upload says “partly succeeded”?** Multi-file uploads are not transactional; retrying overwrites same-named files and never deletes older remote files.
5. **“File exceeds 50 MiB”?** Split or compress it; GitHub also enforces a hard 100 MB per-file limit.
6. **Word file will not open or creation fails?** Close the Word instance holding the file; make sure the progress folder is writable.
7. **macOS says the developer cannot be verified?** Right-click → Open, or run the `xattr` command in section 1.
8. **Two people edit the same file?** The later upload wins; divide work by member folder and back up important files.

## 10. 已知限制 / Known limitations

**中文**
- 只有手动同步，没有实时协作或冲突合并。
- 撤除参考资料后，本机 `Reference` 中的同名副本需手动删除。
- 红点依赖活动日志的动作文案；直接改远端文件不会触发所有红点。
- 双账号、双设备、首次安装的真实验收仍待同僚完成；自动化测试通过不代表没有缺陷。
- Windows 未签名、macOS 未公证，首次运行会有系统提示。
- 需要访问 `api.github.com`；企业代理或防火墙可能导致超时。

**English**
- Manual sync only; no real-time collaboration or conflict merging.
- After removing references, same-named copies in your local `Reference` must be deleted manually.
- Badges depend on activity-log wording; editing files directly on GitHub does not trigger every badge.
- Real two-account/two-device, first-install acceptance by a colleague is still pending; passing automated tests does not prove absence of defects.
- Windows is unsigned and macOS is not notarized, so first launch shows a system warning.
- Access to `api.github.com` is required; corporate proxies or firewalls may cause timeouts.
